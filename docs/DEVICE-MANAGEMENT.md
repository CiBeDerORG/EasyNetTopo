# 设备列表与网络节点归属

## 目标与核心模型

设备列表以 EasyTier 网络节点为管理边界。用户先选择一个网络节点（包括本机入口节点、远端 Peer 和已登记的历史离线节点），页面只展示该节点下的设备；未关联节点的旧设备通过“未关联网络节点”入口继续管理。

网络节点仍由网络节点模块提供，设备模块只引用稳定身份 `network_key + peer_id`，不复制网络节点实时 IP、公网 IP、位置、连接、路由等属性。

一个网络节点可以有一条基础“节点设备”记录、多个直属设备和多个网关组。网关组不是设备记录，而是设备层级中的父级实体：

```text
网络节点
├── 节点设备（系统同步，独立标识）
├── 直属设备
│   └── 设备服务（后续阶段）
└── 网关组
    ├── 网关自身设备（可选，每组最多一台）
    ├── 下挂设备
    │   └── 设备服务（后续阶段）
    └── 网关发现（后续阶段）
```

网关组暂不支持无限嵌套；设备只属于一个网络节点，并且可以是节点直属设备或属于一个网关组。

## 节点身份与设备字段

- `network_key + peer_id` 是设备归属的网络节点作用域；同一节点下允许多条普通设备记录。
- `is_node_device=1` 只用于网络节点自动同步生成的基础设备记录；每个网络节点最多一条。
- `is_node_device=0` 的记录是普通设备，仍可使用相同的 `network_key + peer_id` 归属到该节点。
- 旧版唯一索引 `idx_devices_network_node` 迁移为仅约束 `is_node_device=1` 的部分唯一索引，避免同一节点只能登记一台设备。
- `gateway_group_id` 是普通设备与网关组之间的可选关联；`is_gateway=1` 表示该设备是网关组的网关自身设备，而不是“网关/非网关”两类平铺资产的旧分类。
- 每个网关组最多绑定一台 `is_gateway=1` 的网关自身设备；其他组内设备为下挂设备。
- 网关组必须归属于一个明确的 `network_key + peer_id`。
- 旧版 `device_groups/group_id` 接口保留兼容，不再作为网关组使用。

## 网关组规则

- 一个网络节点可以有多个网关组。
- 网关组可以暂时没有网关自身设备；此时仍可维护组内设备，但不能执行网关发现。
- 网关自身设备必须属于对应网关组，且该组最多一台。
- 下挂设备与网关组必须属于同一个网络节点。
- 删除网关组时，不删除组内设备；将其全部转为当前网络节点的直属设备，并清除网关自身标记。
- 网关组名称只要求在同一网络节点内唯一。

## 节点选择与历史数据

- 页面顶部选择“所处节点”，选择状态写入 URL 查询参数，刷新后恢复。
- 节点选项合并当前入口实时可见的网络节点与数据库中已有的节点设备；暂时离线的历史节点仍可进入并管理设备。
- 设备列表 API 支持按 `network_key + peer_id` 筛选；`unassigned=true` 用于读取旧版未关联节点的设备。
- 创建普通设备时默认继承当前选择的网络节点；在“未关联网络节点”视图中，可以选择目标节点将旧设备迁入。
- 编辑节点设备不允许修改其网络节点身份，也不允许将节点设备放入网关组。
- 编辑已归属网络节点的直属网关设备时，如果设备管理 IP 为空，将从该节点 EasyTier route.proxy_cidrs 的第一个有效 IPv4 代理网段推导第一个可用主机地址并作为表单默认值（如 192.168.10.0/24 → 192.168.10.1）。同一个节点由 network_key + peer_id 精确匹配，不能误用其他节点的代理网段。
- 已填写的 IP、非网关设备、下级网关设备、离线且没有实时代理网段的设备均不自动修改；/31、/32、异常 CIDR 不作为自动填充候选。该 IP 只是建议地址，不代表设备在线或真实占用；用户可在保存前修改。
- 节点自动补充继续使用原有幂等同步逻辑，只查询/创建 `is_node_device=1` 的基础设备记录，不会把普通设备误认为节点设备。
- 节点基础设备不可通过普通设备删除操作删除，避免节点下的设备失去管理入口。
- 离线节点和其历史设备不会因实时路由暂时不可见而被删除。

## 设备分类与类型

- 每台设备有一个用户可自定义的设备类型名称，例如“X86 软路由”“群晖 NAS”。
- `semantic_kinds` 是设备分类与能力的语义标签多选字段。当前内置标签：路由器、服务器、OpenWrt、手机、电脑、平板、电视、NAS、Linux、Android、其他；当前设备页面不再使用独立的自定义设备类型名称。
- `openwrt` 语义标签本身就是 OpenWrt 标识；不再提供独立的 `is_openwrt` 开关，也不要求额外选择“路由器”语义。标记 OpenWrt 的设备必须填写 RFC1918 IPv4 管理地址。
- 历史数据库 `is_openwrt` 字段仅作为兼容镜像：旧记录为 true 且缺少 `openwrt` 语义时，读取时会在返回结果中补充该语义；启动过程不会改写历史数据，设备下一次保存时再按当前语义更新兼容字段。
- RPCD 使用设备唯一管理 IP、协议和端口，固定访问 `/ubus`；不提供多线路 IP。
- RPCD 用户名和密钥保存在 `device_openwrt_configs` 子表中。
- 密钥使用 AES-GCM 加密，密钥文件为数据目录下 `.device-openwrt-sealing-key`，权限必须为 0600；密钥损坏或权限不安全时拒绝启动，不自动重置。备份时必须同时备份 SQLite 数据库和该密钥文件。
- API 永不返回明文密钥。修改 RPCD 地址参数或用户名时，必须重新输入密钥；相同参数下留空表示保留原密钥。
- 取消 OpenWrt 语义标签或删除设备时，级联清除该设备的 RPCD 配置。

## API

- GET/POST `/api/v1/device-groups`（旧版通用设备分组接口，保留兼容）
- PATCH/DELETE `/api/v1/device-groups/{id}`（保留兼容）
- GET `/api/v1/devices?network_key=...&peer_id=...`（读取指定网络节点下设备）
- GET `/api/v1/devices?unassigned=true`（读取未关联节点的旧设备）
- GET/POST `/api/v1/devices`
- PATCH/DELETE `/api/v1/devices/{id}`
- GET `/api/v1/devices/network-nodes`（读取已登记的节点基础设备，用于补齐历史离线节点选择项）
- GET/POST `/api/v1/devices/network-nodes/sync`（读取自动补充状态、幂等同步当前实时节点）
- GET/POST `/api/v1/gateway-groups?network_key=...&peer_id=...`
- PATCH/DELETE `/api/v1/gateway-groups/{id}`
- GET/PUT/DELETE `/api/v1/devices/{id}/openwrt`
- GET `/api/v1/devices/{id}/openwrt/discovery/{devices|adb}`：使用保存的 RPCD 凭据登录并调用 Easy Discovery 的 `list`，只读取路由器已有快照
- POST `/api/v1/devices/{id}/openwrt/discovery/{devices|adb}`：调用 `scan` 主动发现并返回本次结果，同时按网络节点与网关关系自动添加新发现设备；返回的 `import.created/existing/skipped` 为自动导入统计，要求管理员会话和同源请求标记；不得由 GET 隐式触发

所有接口要求管理员会话；写接口要求同源请求标记。OpenWrt 密钥只在服务端解封供后续 RPCD 客户端使用。

## 页面

- 工作台独立入口 `/devices`。
- 顶部节点选择器；选择后只显示该节点下的节点设备、直属设备和网关组。
- 网关组内提供“添加下挂设备”；直属设备区提供“添加直属设备”。
- 每个网关组展示网关自身设备和下挂设备数量，可重命名或删除。
- 节点设备、普通设备、网关自身设备使用不同标识。
- 未关联节点的旧设备保留在独立筛选项，可迁入选定网络节点。
- 已保存 RPCD 账号且标记 OpenWrt 的网关设备卡片显示「服务发现」和「ADB 发现」按钮；打开弹窗仅按需读取快照，点击「开始扫描」才会扫描和自动入库。结果展示扫描状态、时间、数量、来源错误、入库计数及条目预览。
- 自动导入只使用 `scan` 的当前成功或部分成功结果，失败时保留的旧快照不会被导入。新设备归属当前网关已有的网关组并继承所属网络节点；同一网络节点内按 MAC 或 IP 去重，已存在时不修改名称、类型、IP、分组或笔记。无合法 MAC/IP 的条目跳过；ADB 同一设备多个端点尽量按地址去重，不把端点数量视为设备数量。
- 设备发现状态按网关和来源分别记录（普通服务发现、ADB 发现），设备卡片展示聚合状态：任一来源仍在线则在线；有发现记录但所有来源均离线则离线；从未被发现的手工设备保持未知、不误报离线。普通服务发现中 `recent/lease` 代表本次观测在线，`cached` 是历史缓存、不算在线；ADB 当前扫描返回的端点算本次观测在线。
- 只有 `status=ok` 且 `truncated=false` 的完整扫描才会将该网关、该来源此前观测到但本次缺席的设备标记为离线。部分成功或结果截断时，只更新明确观测到的设备为在线，不将缺席设备批量标记离线。服务发现和 ADB 的状态独立同步，避免某一来源未发现设备就覆盖另一来源的在线状态。
- 对接 `luci-app-easy-discovery` 中的 `easy-discovery.devices`、`easy-discovery.adb` 两个固定 RPCD 对象的 `list/scan`，不开放自由调用对象或 shell 命令。RPCD 凭据只在后端解封；后端固定访问设备 RFC1918 IPv4 管理 IP 的 `/ubus`，禁止代理重定向和系统 HTTP 代理；HTTPS 严格验证证书，不关闭校验；扫描超时及响应体有上限。
- OpenWrt 的接口授权须为专用账号授予相应设备或 ADB 的 `list`/`scan` 权限。ADB 只提供无线连接端点发现，不执行配对、连接或远程指令。
- 页面复用全局认证、主题和工作台外壳，不加载主机商店的应用目录、Docker 清单和执行任务轮询。

## 分期边界

当前基础层级阶段只实现节点选择、节点范围筛选、直属设备、网关组、网关自身设备与下挂设备的登记管理。

后续阶段再实现：
- 网关组绑定 EasyTier 网络实例、配置快照、子网代理/网段映射规则与地址推导。
- 发现结果的人工逐项选择、差异审核、属性合并、ADB 配对与自动化任务；当前扫描成功后会按网络节点内 MAC/IP 保守去重，并自动创建新设备，不覆盖历史或手工维护的设备。
- 设备服务的增删改查与网关服务展示。

明确不纳入：
- ADB 配对、连接、设备控制、投屏、触控和群控。
- 自动化中心、工作流和定时任务。
- 多线路 IP 管理、临时 IP、线路选择、自动切换和故障回退。
- 根据 EasyTier 路由表自动判定网关设备。
