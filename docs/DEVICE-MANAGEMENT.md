# 设备列表与网络节点同步

## 目标

EasyNetTopo 的设备列表用于登记和分类物理设备/终端。EasyTier 网络节点作为设备列表的基础数据来源，并以“节点设备”标识；设备资产与网络节点仍保持职责分离。

## 设备分类与类型

- 设备分组暂时固定为“网关设备”和“非网关设备”，由设备的 `is_gateway` 字段人工选择；不根据入口实例、节点在线状态或路由角色自动推断。
- 每台设备有一个用户可自定义的设备类型名称，例如“X86 软路由”“群晖 NAS”。
- `semantic_kinds` 是设备语义标签多选字段。当前内置标签：路由器、服务器、OpenWrt、手机、电脑、平板、电视、NAS、Linux、Android、其他。一个设备可以同时具备多个标签。
- 节点设备由 `is_node_device` 标识。具有有效 `network_key + peer_id` 关联身份的设备会自动标记为节点设备。
- 旧版 `device_type` 枚举值会在读取界面时映射为可读名称；数据库升级会为旧设备补齐对应语义标签。

## 网络节点初始化与自动补充

- 空设备列表提供“初始化网络节点”入口。初始化会读取当前可见网络节点，并按 `network_key + peer_id` 幂等创建基础设备。
- 初始化完成后，持久化开启“新节点自动补充”。设备列表页面打开期间，前端沿用网络节点的 15 秒刷新周期检查新增节点并补充设备。
- 同一个网络身份最多关联一条设备；已有手工登记并关联该节点的设备会被标记为节点设备，不覆盖其名称、类型、分组或其他人工资料。
- 新补充的节点默认归入“非网关设备”，设备类型名称为“通用设备”，不预设路由器/服务器等语义标签。
- 节点离线、暂时不可见或入口主机不可用时，不删除节点设备。
- 自动同步只补充从未同步过的节点。用户主动删除节点设备后会保留同步去重记录，后续刷新不会反复重建；若节点重新出现也不会覆盖用户删除决定。
- 节点别名、Peer ID、虚拟 IP、连接、路由和地理位置仍由网络节点模块提供；设备记录只保存稳定身份，不复制节点实时属性。

## 不纳入本期

- ADB 配对、连接、设备控制、投屏、触控和群控。
- 自动化中心、工作流和定时任务。
- 多线路 IP 管理、临时 IP、线路选择、自动切换和故障回退。
- 复制网络节点的实时 IP、公网 IP、位置、连接和路由数据。
- 根据 EasyTier 路由表自动判定网关设备。

## OpenWrt 专属配置

- OpenWrt 是设备的专属能力标识，设备必须具有“路由器”语义标签。
- OpenWrt 设备必须填写 RFC1918 IPv4 管理地址。
- RPCD 使用设备唯一管理 IP、协议和端口，固定访问 `/ubus`；不提供多线路 IP。
- RPCD 用户名和密钥保存在 `device_openwrt_configs` 子表中。
- 密钥使用 AES-GCM 加密，密钥文件为数据目录下 `.device-openwrt-sealing-key`，权限必须为 0600；密钥损坏或权限不安全时拒绝启动，不自动重置。备份时必须同时备份 SQLite 数据库和该密钥文件。
- API 永不返回明文密钥。修改 RPCD 地址参数或用户名时，必须重新输入密钥；相同参数下留空表示保留原密钥。
- 取消 OpenWrt 标识或删除设备时，级联清除该设备的 RPCD 配置。

## API

- GET/POST `/api/v1/device-groups`（保留旧版接口兼容）
- PATCH/DELETE `/api/v1/device-groups/{id}`（保留旧版接口兼容）
- GET/POST `/api/v1/devices`
- PATCH/DELETE `/api/v1/devices/{id}`
- GET/POST `/api/v1/devices/network-nodes/sync`（读取状态、幂等同步当前节点并开启自动补充）
- GET/PUT/DELETE `/api/v1/devices/{id}/openwrt`

所有接口要求管理员会话；写接口要求同源请求标记。OpenWrt 密钥只在服务端解封供后续 RPCD 客户端使用。

## 页面

设备列表通过工作台侧栏独立入口 `/devices` 进入。页面复用全局认证、主题和工作台外壳，不加载主机商店的应用目录、Docker 清单和执行任务轮询。网关/非网关是设备资产分类；网络节点关联选择和节点实时信息继续由网络节点模块提供。
