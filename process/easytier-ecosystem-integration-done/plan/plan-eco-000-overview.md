## 1. 目标、范围与前置条件

目标是让用户在 EasyTier Web 中按“网络拓扑 → 网络节点 → 类型 → 服务/设备组 → 设备”浏览资源，查看地点、型号和可查询状态，进入访问设置与导航。保留既有登录、用户管理、权限、网络配置和路由行为。

### 本期交付

- 基于实际用户管理实现分支的页面与组件清单、接口能力清单及缺口记录。
- 拓扑、节点详情、资源详情、访问设置、导航入口的页面设计，包含主要流程、字段、状态、权限与窄屏行为。
- 在已有接口支持范围内完成前端接入和操作反馈；接口缺失的能力明确显示未支持/未知，不模拟保存或执行成功。
- 独立页面验证、统一入口接线、真实接口联调以及兼容性验收记录。

本计划不新增资源后端、数据库迁移、网关执行器、站点常驻代理或外部系统部署。页面需要但基线没有的接口先记录缺口，不自动转为后端开发任务。不重做用户管理，不引入 Navloop 的连接框架，不新增状态轮询、心跳长连接、WebSocket/SSE 状态订阅、后台扫描、自动重试队列、定时任务或调度器。ECO-C01 至 ECO-C09 及额外地点/依赖多视图已不采纳；ECO-14 的 deploy 明确后置。

## 2. 页面范围与主要流程

沿用基线已有 Vue、PrimeVue、主题、i18n 和布局；不切换前端框架。以下是页面职责，不预设必须新增相同数量的顶级路由，能够复用已有详情页或抽屉时优先复用。

| 页面/区域 | 主要内容与操作 | 必须覆盖的状态 | 需求 |
| --- | --- | --- | --- |
| 网络拓扑 | 当前网络、节点与真实连线；展开节点下的服务/设备组；选择节点进入详情；保留已明确的网络/地点筛选 | 加载、空网络、查询失败、未知连线、多网络宿主；连接边与资源包含关系区分 | ECO-01、ECO-03、ECO-10 |
| 节点详情及资料表单 | 名称、地点、厂商/型号、系统/架构、网络成员；服务与设备组入口；新增记录表现为待接入 | 人工资料与接口资料区分；无字段/无保存接口、无权限、保存失败；不显示已部署 | ECO-09、ECO-10 |
| 服务/设备组/设备详情 | 统一资源归属与类型；组内设备；Android/家居子类型与已有可用操作；按需读取状态 | 未接入/未配对、无接口、无操作权限、失败/未知；同名外部对象不误合并 | ECO-03、ECO-04、ECO-05 |
| 资源访问设置 | 公网许可、映射规则和导航发布分别表达；选择实际端点、入口及网络上下文 | 未配置、缺少入口、未支持、待确认、失败与已确认结果；保存不等于生效 | ECO-11、ECO-12、ECO-13 |
| 导航入口 | 展示已发布资源及可用访问方式；跳转到资源或其受控端点；可返回所属节点 | 私有入口、无权限、未知/失效地址；不因显示导航自动开放公网 | ECO-01、ECO-13 |
| 既有管理入口 | 保留登录、用户与权限管理、原网络配置入口；资源操作反馈留在相关页面 | 会话失效、无权限、未保存表单及操作结果 | ECO-06、ECO-07、ECO-15 |

主流程：登录 → 选择网络 → 选择节点 → 查看服务/设备组 → 打开资源详情 → 根据实际能力访问或配置 → 查看请求结果 → 必要时手动刷新。拓扑提供可键盘访问的节点信息和同内容的文本表达，不扩展为新的全局搜索或多视图产品。

### 与独立 Web 美化需求的边界

[PLAN-WUI](../../web-ui-optimization-done/README.md)独立负责既有页面交互与视觉；本计划不认领其工作包，也不等待它才能开展拓扑设计。两者均复用已完成用户管理，不改动 `config-server` 的客户端连接、认证或配置下发。

若同时改动 MainPage、路由、公共样式/主题、文案、脚本或 API 客户端，协调者必须先指定跨需求唯一写入安排和交接顺序；不得因拆成不同目录或 worktree 就并行抢写同一文件。
