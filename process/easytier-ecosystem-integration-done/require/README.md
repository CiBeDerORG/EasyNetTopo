## 1. 产品主模型：拓扑、节点、类型与资源

页面设计复用用户管理实现分支的登录与工作台。用户先查看网络拓扑，选择一个网络节点，再查看它承载或接入的服务、设备组和设备。EasyADB、家居中枢等按实际已有接口提供能力；导航入口不要求接入 Navloop 的运行框架。

```text
网络拓扑
├─ 网络节点 A（名称、地点、厂商/型号、系统、网络状态）
│  ├─ 服务类
│  │  ├─ 服务：NAS 管理
│  │  └─ 服务：家居中枢 Web
│  ├─ 设备组类
│  │  ├─ Android 设备组
│  │  │  ├─ 设备：手机 A（EasyADB）
│  │  │  └─ 设备：手机 B（EasyADB）
│  │  └─ 智能家居设备组
│  │     ├─ 设备：灯（家居中枢）
│  │     └─ 设备：温度传感器（家居中枢）
│  └─ 后续扩展类型
└─ 网络节点 B（同样的类型与资源结构）
```

“服务类”“设备组类”是节点下的类型入口；设备组是容器，手机、灯等是设备资源。设备继续记录子类型和能力，例如 Android、照明、传感器，以决定可显示字段与可执行动作。新增类型必须声明其字段、允许的子对象、接入方式及能力，不能只增加一个自由文本标签就获得执行权限。

上述树表示资源归属。网络节点之间的直连、中继等连线表示真实网络关系，两种关系共同构成拓扑视图，但必须使用不同线型/图例。服务或设备归属某节点，不等于它是独立 EasyTier peer；同属节点也不自动证明彼此可通信。

### 页面组织

| 入口/区域 | 目标行为 |
| --- | --- |
| 网络拓扑（主入口） | 按网络或地点筛选节点，查看实际连接，展开节点的类型与下挂资源 |
| 节点详情 | 基础资料、网络成员/运行实例、类型目录、接入能力、状态和相关操作 |
| 资源详情 | 设备或服务的信息、业务操作、访问端点、公网开关、端口映射及导航设置 |
| 导航服务 | 展示从资源发布的访问入口，并能回到所属节点；其余列表能力以基线已有功能为准 |
| 操作反馈（相关详情页） | 展示用户此次操作的响应和可查询结果，不新增调度或批量任务中心 |
| 管理 | 复用用户管理分支已有用户、权限与管理入口；资源相关配置按本需求组织，不新增独立运维平台 |

EasyADB 和智能家居设备统一从节点下的设备组进入。已有列表与导航使用同一资源记录，不另建资产库，也不据此新增第 14 节已不采纳的全局搜索或多视图功能。保留用户管理实现分支的网络配置与路由兼容性；本地 [Web 路由](../../../easytier-web/frontend/src/main.ts)仅作历史源码定位，实际设计以核对后的实现分支为准。

## 3. 网络节点资料与生命周期

网络节点代表可登记、可管理的宿主。允许记录尚未入网的计划节点，后续再与实际登记身份绑定；节点 ID 不使用 IP、显示名称或易变化的 peer ID。

| 资料分类 | 建议字段 | 来源与规则 |
| --- | --- | --- |
| 基础标识 | node_id、display_name、登记身份引用、标签、说明 | 沿用已有归属；新平台引用必须能追溯 user_id/machine_id |
| 地点 | site/location、房间、机柜/位置说明 | 人工维护；地图坐标可选，不强制采集精确位置 |
| 硬件 | manufacturer、device_model、宿主类型 | 人工补充或可信采集；未知显示未知，不从 hostname 猜测 |
| 系统 | OS/版本、CPU 架构、运行环境与可用能力 | 记录采集来源和时间；属于后期 deploy 的兼容依据 |
| 网络 | 成员网络、运行实例、虚拟地址、连接路径、控制通道状态 | 来自对应网络/实例，不能混成节点唯一 IP |
| 集成 | EasyADB/家居/Navloom 来源实例、连接器引用 | 引用其部署和能力，不在资料里保存明文凭据 |
| 生命周期 | 待接入、已绑定、控制通道在线/离线及最近确认时间 | 资料创建、方案生成、安装完成和成功入网分别表达 |

人工资料与接口返回资料分开管理，记录字段来源与更新时间；重新查询和已有底层数据更新不得覆盖人工地点或型号修正，不新增采集心跳。查询失败时可保留最后已知资料，并标明查询失败及最后观察时间。

同一宿主加入多个网络时，拓扑按所选网络展示对应成员和连线，下挂资源仍引用同一个节点。运行实例、网络成员和 runtime peer 独立关联；不能把多网络宿主悄悄当成不同网络之间的路由器。

### 新增节点的近期行为

先登记节点资料和预期接入方式，显示“待接入”；已有宿主通过经过授权的绑定流程关联到该记录，不能仅因名字相同自动合并。当前不执行 deploy 项目的安装编排。

删除、迁移节点或设备组时先展示下挂设备/服务、映射和导航引用的影响。建议禁止无提示级联删除；资源迁移需要重新验证访问路径和授权，不继承原节点的公网入口作为默认成功状态。

## 4. 类型、设备组、设备与服务

| 对象/字段建议 | 用途与约束 |
| --- | --- |
| node_id | 节点资料与现有宿主身份的稳定关联 |
| type_id / resource_kind | 节点下的类型分类与资源行为；首期 service、device_group、device，后续可扩展 |
| resource_id | 服务、设备组或设备的稳定平台标识，与名称/IP解耦 |
| parent_resource_id | 设备指向其设备组；组与设备必须属于同一节点，禁止循环和跨归属挂载 |
| device_type | 统一设备下的专业子类型，例如 android、light、sensor；不是新增人员角色 |
| source_instance_id + external_id | 关联 EasyADB、家居等来源的对象；不同部署不能因同名而合并 |
| connector_id | 如已有接口需要，引用本地资源的能力来源；与人员和网络节点身份分别管理，不据此新建常驻连接器或心跳服务 |
| endpoint_id | 某个设备/服务实际可用的访问端点；一个资源可有多个端点 |
| operation_id | 关联动作、执行、结果与审计；超时不能推断未执行 |

设备组是资源组织容器，不是用户权限组或一个新网络节点；首期不因操作设备组就自动为全部设备开启公网或发布导航。跨节点分组和设备多归属暂不隐式引入，后续有明确需求再扩展。

服务描述可访问应用或协议能力；设备描述手机、家居等对象。家居中枢可以作为服务，灯作为设备，其可控属性仍由原中枢维护。设备详情可列出原中枢实体/能力引用，避免把每个传感属性都创建为一台物理设备。

节点归属用于确定访问路径，来源实例用于标明原系统身份；来源适配器不能仅按客户端提交的 node_id 改写资源归属。资源可被搜索/导航引用多次，但只有一份权威记录。

## 5. 统一状态与访问能力

每个设备/服务详情提供统一的访问设置：公网访问开关、端口映射列表、导航发布设置；具体可用方式由其访问端点和执行侧能力决定。

### 状态查询方式：普通请求与响应

- 进入页面、切换所选节点/资源、用户点击刷新，以及一次明确操作结束后，按需要调用相关状态接口；复用已有请求封装、认证、错误处理与可用批量接口。
- 页面空闲时不新增轮询或自动刷新。不增加前端 interval/递归 timeout 轮询、后端 cron/定时任务、后台状态扫描、自动重试队列、调度器，也不新建用于状态同步的心跳、长连接或 WebSocket/SSE 订阅。普通请求超时控制不等于周期状态任务。
- 展示接口最近一次返回的状态、来源及查询时间，不承诺实时更新。请求失败、超时、无权限、未提供状态接口分别反馈；只有接口明确返回离线时才显示离线，查询失败不能直接推断设备离线。
- 若操作返回已受理或结果未知，显示该实际结果；可由用户手动刷新查询后续结果，不自动循环查询或重新执行。旧请求结果不得覆盖切换后的对象。
- 缺少状态或执行接口时标明未支持/未知并记录缺口，不用模拟成功或新增后台机制填补页面。新增页面的此项约束不改变 EasyTier 现有底层组网机制。

| 状态维度 | 展示内容 |
| --- | --- |
| 节点连接 | 已有接口返回的控制会话、所选网络路径及来源 |
| 设备/服务健康 | 按需接口返回的业务状态、观察/查询时间，或未知/查询失败 |
| 访问授权 | 当前用户对具体资源与动作的权限 |
| 动作结果 | 已受理、执行中、成功、失败、结果未知 |
| 公网发布 | 期望配置及接口可确认的应用结果；外部可达性缺少证据时显示未知，不新增持续探测服务 |
| 导航发布 | 是否显示、谁可见、当前可打开的访问入口 |

建议访问端点记录协议、目标地址/端口或受控 API、执行连接器、网络/实例上下文以及用途。USB 手机、Zigbee 或蓝牙设备可能没有可直接映射的 IP/端口，此时应接入宿主/中枢的授权 Web/API 入口；未提供访问端点时，设置保留“关闭/未配置”状态并说明缺少什么能力。

不能为了满足统一界面给设备编造端口，也不能在无设备级隔离的情况下把整个家居中枢或 ADB 管理接口当作“只开放这一台设备”。支持的原生协议端点可显式配置，默认不开放全部端口。

节点自身的 Web 管理、SSH 等访问能力也可登记为服务后配置入口；节点级监听能力不等于对该宿主全部服务的授权。

## 6. 公网访问与端口映射

公网访问、端口映射和导航发布是分别保存的配置。建议新资源公网访问默认关闭，端口映射按规则启用，导航默认未发布；这些默认值是设计建议，未在代码生效。

### 映射与公网入口

每个设备/服务可配置多条映射，一条规则指向一个明确的 endpoint。建议字段如下：

| 配置项 | 含义 |
| --- | --- |
| mapping_id、resource_id、endpoint_id | 明确发布哪个资源的哪项访问能力 |
| enabled / exposure_scope | 规则是否期望启用，范围为内网/overlay 或公网；公网模式受资源公网开关约束 |
| ingress_node_id 或 gateway_id | 哪个执行节点/网关监听入口；可与资源所属节点不同 |
| network_id / instance_id / connector_id | 入口到目标的网络路径或执行上下文 |
| transport、listen_address、listen_port | TCP/UDP 等监听参数，校验有效端口、占用与平台能力 |
| target_address、target_port | 从 endpoint 解析的目标；修改须重新验证资源归属和可达路径 |
| domain、TLS、application_protocol | HTTP/HTTPS 等应用入口按需配置；不是通用 TCP 转发自动具备的能力 |
| access_policy、限制与有效期 | 哪些人/来源可访问、如何认证以及必要边界，不因“公网可达”自动匿名开放 |

示意链路为：公网客户端 → 入口节点/网关的地址与端口 → EasyTier 所选网络/连接器 → 目标节点下的设备或服务端点。

节点不一定有可用公网地址。没有可用入口时应显示“待配置公网入口”，可以保存草稿，但不能把开关保存成功等同于已经可从公网访问。也不能仅把 bind_ip 改成 0.0.0.0 就宣称完成公网发布；还需验证实际监听、上游路由/防火墙和访问路径。

TCP/UDP 映射的冲突至少按执行宿主、监听地址、端口、协议及地址覆盖关系判断；不同 EasyTier 实例共享同一宿主端口空间时仍可能冲突。基于域名共用 HTTP 入口需要应用网关明确支持路由规则，不能借此绕过端口冲突。

原始 TCP/UDP 的认证与访问控制按入口和目标协议明确，不能把 Web 登录保护套用为所有协议已受保护的证据。并发申请同一端口必须有冲突仲裁，失败不能破坏既有有效映射。

### 发布、变更与撤销

1. 用户选择资源端点、入口和映射，服务端验证其管理权限、目标范围、端口及运行能力。
2. 通过用户发起的普通操作请求保存/应用配置，以真实响应确认结果；已有接口支持查询时按第 5 节按需读取，不新增任务调度器。没有现成执行能力时记录缺口，不将保存草稿显示为已生效。
3. UI 区分“已保存/待应用/应用失败/已应用”。外部可达性仅展示已有接口可核实的结果及来源/时间，无证据为未知；超时保留未确认状态，不启动周期探测、自动重试或后台协调任务。
4. 关闭公网时撤销全部属于该资源的公网入口；内网专用映射按其独立设置处理。建议撤销同时终止相关活动访问流；执行侧无法确认时显示“撤销待确认”，不能仅依据数据库开关显示完全关闭。
5. 对资源迁移、删除、映射修改做版本校验与串行协调；解除旧入口后再确认新入口，避免残留地址和旧请求恢复已撤销配置。

建议公网开关作为该资源公网入口的总许可，映射仍有各自启用状态；不存在映射或应用入口时，开关只表达意图并显示未就绪。入口共享、端口批量操作和长期连接撤销能力需在后续契约明确。

这部分新增的是资源级发布与编排。应复用适用的现有端口转发及配置同步路径，维护唯一配置所有者；现有 central_network Gateway 的名字不能作为它已具备资源级公网网关能力的证据。

## 7. 添加到导航服务

每个服务/设备详情提供“添加到导航”入口，导航项引用 resource_id 和所选 endpoint/映射，不复制一套独立设备记录。

建议可设置显示名、图标、分类、标签、可见用户/范围、排序及访问方式。设备可链接其受控详情/控制页面；非 HTTP 协议可以展示明确的客户端入口或复制连接信息，不能生成一个假网页地址。

- 加入导航不自动开启公网；内网资源可发布为私有导航项。
- 开启公网不自动向所有人公开导航；可见性、资源权限和入口认证分别执行。
- 导航优先引用资源及端点生成地址；端口、域名或归属变更后更新可用入口，旧入口不可悄悄继续指向错误资源。
- 入口失效时显示不可用及原因，不能自动回退到更宽权限的地址。
- 删除资源时处理关联导航；移除导航只移除展示，不自动删除资源或停用映射。

导航页面在 EasyTier Web 中按常规列表、详情和接口操作设计，优先复用用户管理实现分支的现有能力。将来确需复用 Navloom 的导航数据时，先核对实际 API；本期不引入用户所指 Navloop 的心跳、连接和调度框架，也不把外部项目接入作为页面设计的前置条件。不存在稳定接口时不能宣称已实现跨系统统一登录或全部业务审计。

## 8. 分层职责与浏览器访问

| 组件 | 职责 |
| --- | --- |
| EasyTier Web 前端 | 基于用户管理实现分支设计拓扑、节点资料、资源详情、映射和导航页面，复用现有 Vue/PrimeVue/i18n；状态按需请求 |
| EasyTier Web 后端 | 复用已有认证和普通查询/操作接口；所需资源、授权与状态接口缺口单独记录，不为页面新增周期任务 |
| EasyTier Core / 原生宿主 | 保持已有网络策略、协议和原生能力边界，不吸收整个资源平台 |
| 导航数据来源 | 先复用现有资源和接口；不要求导入 Navloop 运行框架 |
| EasyADB / 家居接口适配 | 使用实际可用接口进行按需查询或明确操作，保留来源映射；不建立新增状态同步长连接 |
| 已有执行侧 / 访问网关 | 仅复用可验证的访问与映射能力及查询接口；能力不足记录缺口，不将新建站点常驻代理作为页面设计要求 |

平台代码放在 easytier-web 的明确领域模块；本地设备能力放在需要的执行侧。不能通过向网络 RemoteClient 或 Core 添加所有业务来实现统一 Web。依据：[Core 架构](../../../docs/core-architecture.md)、[领域上下文](../../../CONTEXT.md)。

EasyTier Web 后端可达不代表用户浏览器可达。私有导航需要客户端已接入网络或使用受保护应用网关；公网入口必须确有外部可达路径。HTTP/WebSocket 代理需处理 Origin、Cookie、TLS、路径及流式连接，限制目标为获授权的登记端点，避免成为任意地址代理。

[@easytier/browser](../../../easytier-js/browser/README.md)已有 WS/WSS peers 与 overlay IPv4 TCP，要求 WebAssembly JSPI，且没有 TUN、STUN、打洞或原生监听。它不自动让浏览器导航、fetch 和 iframe 走虚拟网络，不能代替通用公网/私网访问设计。

## 9. 身份、授权与本地连续性

EasyTier Web 作为平台登录入口，复用用户管理实现分支的账号、权限与现有 OIDC 行为，不在本轮页面设计中重做身份体系。平台人员、节点、能力来源和外部业务设备是不同身份；同名用户不自动合并，外部身份按适用的稳定映射关联，不共享用户表或会话 Cookie。

访问和写入分别校验节点/资源归属及能力。管理账号的权限不自动授予发布公网、控制 Android 或操作家居设备的权限；公共入口对使用者采用何种认证需显式配置。开关“公网访问”表示网络可达范围，不默认表示匿名操作授权。

EasyADB 的设备授权/配对由相应宿主处理；纯设备功能不能靠网络连通替代。家居中枢保留专业协议、实体和本地自动化。页面通过已有接口按需读取已接入设备，不新增自动发现、定期扫描或主动上报机制；L3 组网不保证 mDNS/广播自动跨站点，站点同名内网 IP 通过节点及路径上下文区分。

平台接口不可用时，原有本地自动化按其策略继续。操作请求失败或结果不明时明确反馈，不新增离线动作队列、自动重放或补偿定时任务。公网撤销、平台账号停用、外部凭据失效及设备断网分别表达；不能用其中一个开关声称完成全部撤销。
