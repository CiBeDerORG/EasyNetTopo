## 3. 原始分析提出的设计约束（历史记录）

### 3.1 管理权限不能直接复用当前查询

`Backend::get_group_permissions` 接收 `_user`，但查询没有以该用户 ID 过滤，会查询所有用户关联的权限。当前 Web 路由主要使用 `login_required!`，未发现管理员权限检查接入。

**上线前提：** 修复查询作用域，测试普通用户不会获得管理员权限，再为管理路由接入显式权限校验。不能靠用户名等于 `admin`、前端隐藏菜单或用户提交的角色判断权限。

### 3.2 账号与网络资源的生命周期不同

- 用户名还是设备接入 token；第一阶段保持用户名不可编辑。显示名如有需求应单独建模。
- 删除用户可能级联删除设备、网络、凭据和运行配置；数据库删除也不会自动完成在线运行时清理。
- OIDC、设备自动建号、外部 webhook 映射可能再次生成同名本地账号。直接删除不是可靠的停用机制。
- Web 会话失效、设备配置通道断开、已下发网络的数据面停止是三种不同结果。

**推荐边界：** 第一阶段提供“停用控制台访问”，保留账号和业务数据，拒绝该账号的 Web 登录与后续已认证 HTTP 请求；设备接入和已运行网络保持原策略，界面明确说明影响。全面冻结设备接入或撤销网络访问另设能力，不能宣传停用账号能使所有离线节点立即断网。此边界已纳入契约 v1；它是目标行为，不是已完成的现状。

### 3.3 历史账号来源不可凭空推断

当前未保存 OIDC `issuer`/`sub` 或账号来源，所有路径写入同一用户表。随机密码哈希不能用来可靠识别“OIDC 账号”。

新建本地账号可以明确标注来源；历史账号显示“来源未记录”。重置入口依据后端确认的本地凭据能力决定，而非通过用户名或哈希格式猜测。启用 OIDC 的部署在上线管理功能前，必须明确身份绑定、同名冲突、停用校验与本地登录策略；不能让 OIDC 再次登录绕过停用。

建议外部身份使用 `(issuer, subject)` 稳定绑定；已有按用户名合并的关系需要兼容/人工确认策略，不能把同名身份自动绑定为管理员。完整的 IdP 管理界面可后置，身份边界本身不能后置。

### 3.4 凭据与管理员写操作要有完整保护

当前浏览器在登录、注册和改密时先做 MD5 摘要，服务端再通过 `password_auth` 哈希验证；新增重置流程必须明确与旧客户端的兼容策略，不得只有一端改变输入格式，也不能把 MD5 当作传输保护。

[ApiClient](https://github.com/CiBeDerORG/EasyTier/blob/e307dadb4812fc42a43e4e7f210f11ffa980e02e/easytier-web/frontend/src/modules/api.ts#L234)记录完整 Axios 响应对象，可能连带请求上下文。创建或重置流程接入前应移除或脱敏相关凭据日志；一次性凭据不能进入 toast、URL、审计内容或持久列表。

管理员写 API 使用现有 Cookie 认证时，还需验证部署方式下的同源/CSRF 与 Cookie 策略。当前通用 Session/CORS 配置不等于新增管理端点的保护已经完成。

## 4. 用户与权限模型建议

第一阶段使用两种产品角色，复用现有组与权限关系，避免再增加一个独立可变的 `is_admin` 真相：

| 操作 | 普通用户 | 平台管理员 |
| --- | --- | --- |
| 查看本人身份、退出、适用时修改本人密码 | 允许 | 允许 |
| 管理本人设备和网络 | 保持当前权限与归属规则 | 保持当前权限与归属规则 |
| 查看账号列表与有限账号元数据 | 不允许 | 允许 |
| 创建本地账号、停用/恢复控制台访问 | 不允许 | 允许，受自保护规则约束 |
| 重置适用账号的本地密码、注销 Web 会话 | 不允许 | 允许，记录审计 |
| 分配管理员/普通用户角色 | 不允许 | 允许，禁止产生零个有效管理员 |
| 直接调用其他用户的网络管理 API | 继续受资源归属与业务授权限制 | 账号管理权限不新增跨用户业务 API 授权 |

可新增明确的 `users.manage` 权限并赋给 `admins` 组，产品角色映射为 `admin` / `user`。任意自定义角色、组织权限和网络 ACL 不纳入第一阶段；网络 ACL 继续使用现有业务授权模型。

**信任边界：** 此方案的平台管理员属于受信运维角色。掌握临时密码的管理员能够以目标账号登录；用户名列表也会集中暴露当前作为设备接入 token 的标识。因此，保持业务 API 的资源归属检查不代表用户数据对平台管理员具有强隔离。如果需要管理员无法取得用户凭据或间接访问用户资源，必须另行设计凭据交付/恢复和独立设备接入 token，不能仅靠隐藏操作入口实现。

| ID | 需求 | 可观察结果与限制 |
| --- | --- | --- |
| UM-01 | 当前用户与管理能力 | 登录后获取本人 ID、角色和能力；管理菜单依据服务端能力显示；直接调用管理 API 仍受后端保护 |
| UM-02 | 用户列表 | 搜索用户名、按角色/访问状态筛选、服务端分页；展示用户名、角色、控制台访问状态、可确认的来源及时间；缺失历史时间显示未知 |
| UM-03 | 管理员创建本地账号 | 明确用户名规则、唯一性和凭据策略；默认普通用户；关闭自助注册不阻止授权管理员创建；并发重复请求不产生重复账号 |
| UM-04 | 停用/恢复控制台访问 | 确认目标与影响；停用后拒绝本地/OIDC Web 登录及旧 Web 会话；恢复后必须重新登录，不能复活旧会话；资源不删除 |
| UM-05 | 重置本地密码 | 与本人改密分开；仅针对可确认支持本地凭据的账号；旧密码及旧 Web 会话失效；临时凭据登录后必须改密再访问工作区 |
| UM-06 | 分配角色 | 服务端重新授权每次操作；避免自降权/自停用导致失联；并发请求也不能停用或降级最后一个有效管理员 |
| UM-07 | 主动注销账号的全部 Web 会话 | 不依赖改密；说明目标是浏览器会话；注销操作和停用/角色变更共享明确的会话撤销机制 |
| UM-08 | 注册策略反馈 | 登录页读取公开的非敏感策略；关闭注册时不显示可用注册流程；服务器仍强制执行；与设备/OIDC 自动建号分别表述 |
| UM-09 | 管理审计 | 创建、停用/恢复、重置、改角色、撤销会话记录 actor/target/action/time/result；不记录密码、摘要或重置 token；第一阶段提供管理员只读查看入口 |
| UM-10 | 首个管理员与恢复路径 | 识别已有管理员并保持兼容；新增部署有明确初始化与恢复方式，不将首个普通注册用户自动提升为管理员，不扩大可预测预置凭据的使用 |

临时密码是便于自建部署的默认建议：不依赖邮件服务，管理员按既定安全渠道交付，首次登录强制改密。过期时间、密码策略和管理员操作的再次认证要求需在实现前定案；一次性重置链接可作为替代方案，但需要完整的签发、过期、消费及投递设计。

第一阶段不提供：用户名重命名、物理删除账号、资源转移、账号合并、组织/团队、邮件邀请、任意自定义角色、配额计费或专用代登录入口。它们进入后续需求池，避免单个账号操作暗含跨租户资源变更；不提供代登录入口不等于管理员无法使用其掌握的临时凭据登录。

## 6. 页面与操作流程

建议在 Web 工作区新增“管理 → 用户”，与设备、网络导航区分；本人账户菜单继续承载本人改密和退出。

### 用户列表与详情

- 列表：用户名、角色、控制台访问状态、登录方式/来源说明、创建时间、最近成功登录时间、操作。未知信息不得用迁移时间或猜测值填充。
- 顶部：搜索、角色/状态筛选、创建用户；使用服务端稳定排序和分页，限制页大小。
- 详情/抽屉：只展示必要账号信息与最近管理记录；不默认加载网络密钥和完整配置。资源数量可后续增加，不能无意引入全局网络读取权限。
- 状态：加载、无用户、无匹配项、读取失败、无权限、会话失效分别展示。读取失败保留上次数据时标注过期。

### 创建、停用与重置

1. 创建：输入账号信息 → 服务端校验与授权 → 创建成功 → 展示交付提示 → 刷新列表。失败保留非敏感表单并提示对应字段；凭据不用 localStorage 保存。
2. 停用：选择目标 → 显示“控制台访问受影响，设备/网络按既定策略继续”的确认 → 提交 → 以服务端结果更新状态；失败不提前变更为已停用。
3. 重置：确认目标和登录方式 → 再次确认会话影响 → 完成重置 → 按凭据方案交付 → 目标用户首次登录强制改密。拒绝给不适用的身份展示虚假的成功状态。
4. 改角色：显示现角色与目标角色 → 检查服务端保护规则 → 成功后重新读取权限；权限撤销的页面必须停止受保护提交。

新增文案进入现有中英文资源；支持键盘、可访问标签、窄屏和长用户名。403 显示无权限，401 引导重新登录，网络故障提供重试，不能都归为“未登录”。

## 7. 实现边界与接口草案（原始基线，已由契约收敛）

以下保留原始接口草案；对应能力已实现，最终路径、请求和响应以计划第8节契约及代码为准。

| 方法与路径建议 | 用途 | 权限 |
| --- | --- | --- |
| `GET /api/v1/auth/me` | 当前身份、能力及强制改密状态；保留旧登录检查接口兼容性 | 已认证账号，受限登录可读必要信息 |
| `GET /api/v1/auth/policy` | 公开自助注册/OIDC 可用性，不包含账号和密钥 | 公开只读 |
| `GET /api/v1/admin/users` | 搜索、筛选、分页列表 | `users.manage` |
| `POST /api/v1/admin/users` | 创建本地账号 | `users.manage` |
| `GET /api/v1/admin/users/{user_id}` | 受限账号详情 | `users.manage` |
| `PUT /api/v1/admin/users/{user_id}/access` | 设置控制台访问状态；重复设置应幂等 | `users.manage` |
| `PUT /api/v1/admin/users/{user_id}/role` | 设置预定义角色 | `users.manage` |
| `POST /api/v1/admin/users/{user_id}/password-reset` | 重置适用账号的本地凭据 | `users.manage`，核验适用身份 |
| `POST /api/v1/admin/users/{user_id}/revoke-sessions` | 撤销全部 Web 会话 | `users.manage` |
| `GET /api/v1/admin/user-events` | 按目标用户查询管理记录 | `users.manage`，分页只读 |

沿用现有错误包络和 `snake_case` DTO；区分参数错误、未认证、无权限、目标不存在、用户名冲突和最后管理员冲突。禁止返回 `users::Model` 全字段而泄露密码哈希。用户列表只读权限不得隐含成为 `/api/internal/*` 的共享 token。

### 所有权

- `restful/users.rs` 保留认证后端职责，修正权限查询并调用统一账号访问策略。
- 新增 Web 用户管理业务模块，负责角色、访问状态、凭据动作、会话撤销与审计事务；HTTP handler 只做边界处理。
- 数据库通过新增 migration 扩展；角色沿用组/权限关系。新增 `web_login_enabled`、`auth_version`、`must_change_password` 及必要时间字段是建议，不与密码哈希产生相互独立的会话状态。
- 认证摘要应同时考虑当前密码与会话版本；停用/恢复/降权/重置/主动撤销后的旧会话不能继续有效。强制改密状态只能访问必要的身份/改密/退出接口，不能进入管理 API。
- 外部身份单独记录稳定绑定和凭据能力。旧数据来源无法证明时保留未知状态，不能默认都标记成本地账号或允许重置。
- 用户修改、最后管理员保护、权限关系与成功审计需有事务一致性；失败/拒绝审计按明确策略记录，不写入敏感请求体。
- 前端放在 `easytier-web/frontend` 的页面与 HTTP 客户端；不添加到网络配置 `RemoteClient`，不扩散到 portable core 或 GUI 原生账户体系。

## 8. 兼容与部署约束

1. **已有数据**：新增迁移保留用户 ID、用户名、密码哈希、组关系与资源归属；历史时间允许为空；不编辑已发布迁移。
2. **既有管理员**：依据真实组/权限确认，不凭账号名字；初始迁移已有预置账号，初始化和恢复设计必须审查这一事实，不能另造一个默认管理员流程造成竞争。
3. **OIDC**：本地账号管理可以先落地；若目标部署启用 OIDC，稳定绑定/同名冲突/停用与受限登录行为为同阶段上线前提。IdP 管理和组织同步页面可以延后。
4. **外部 Console/webhook**：本地 Web 账号不必等同外部用户目录。第一阶段仅管理本地控制台访问，不宣称能禁用外部 Console 身份或阻止 webhook 映射；保持既有内部配置接口与鉴权边界。
5. **自动建号**：关闭网页注册不等于关闭设备自动建号或 OIDC 自动建号。保留停用记录，自动建号不能覆盖其访问状态；单独展示相关策略。
6. **运行中的网络**：账号访问动作不应意外删库、清空配置或触发 Core 重启。若后续定义全账号冻结，需要独立设计设备拒绝接入、在线通道处理、在途竞态及离线生效边界。
7. **升级与回退**：新旧二进制的认证行为可能不同，不能把降级运行视为继续强制停用。部署方案应明确回退时的访问控制措施和备份恢复边界。

## 11. WUM-001 决定与兼容说明（2026-10-21）

按现有任务实施授权，将本地控制台管理建议收敛为[计划第8节契约 v1.1](../plan/README.md#8-wum-契约-v112026-10-21)；以上源码分析仍描述原始基线。第10节候选项在 v1 中已明确；D-01 已由用户选择 A 解除，兼容登录及默认密码提示以 v1.1 为准：
