# WUM-001：范围与接口契约

需求：[Web 用户管理](../../require/README.md)。计划：[PLAN-WUM](../../plan/README.md)。[返回看板](../README.md)。

## 目标与边界

将首期工作假设收敛为可实现、可验证的契约；本项只处理需求和方案，不编写业务代码。已有建议不等于用户已确认，不凭空引入团队、删除或全设备冻结范围。

## 输入与输出契约

输入为需求草案、现有代码事实及已明确的用户要求。输出记录在计划的契约章节：角色与有效管理员、自操作保护、账号状态与会话撤销、OIDC/历史身份、临时凭据交付、初始化/恢复、DTO/分页/错误/幂等、数据库服务接口、UI props/events 和部署模式。列出稳定字段、可空语义、示例与契约版本，交付 WUM-003/007/008 及后续任务。

产品方向输入：[EasyTier Web 网络拓扑工作台](../../../easytier-ecosystem-integration-done/require/README.md)按节点与类型组织服务、设备组及统一设备，Navloom、EasyADB 与家居能力通过集成接入。当前契约明确平台用户、节点、外部应用账号、业务设备和能力授权的边界；账号管理权限不直接授予设备控制、公网访问配置、端口映射或导航发布权限。这些资源功能、外部适配/单点登录协议及后期 deploy 方案不纳入本项交付，也不作为现有账号管理契约的前置条件。

后续页面设计须遵循上述拓扑文档的最新约束：基于用户指定已完成的用户管理分支，普通接口按需查询，不引入 Navloop 心跳连接、轮询、定时任务或已不采纳的扩展功能。本文件保留原规划记录；本轮未核验实现分支，不因此重开或修改 WUM 执行状态。

## 执行步骤

1. 对照需求草案与当前认证、存储、前端调用，列出已明确行为、工作假设和真正影响下游的待决项。
2. 先定义角色/账号/会话的状态转换及允许操作，再确定登录方式、旧数据、凭据交付和管理员恢复的兼容边界。
