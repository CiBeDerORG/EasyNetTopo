# PREFIX-001：任务名称

复制到 `process/<feature>-<状态>/task/task-<任务编号>-<任务名称>.md` 后填写字段，例如 `task-wum-001-contract.md`。链接同需求根汇总、require/README.md、计划索引、实际对应的计划明细及任务看板；`plans` 填具体计划 ID。一文件只写一个可交接任务，公共契约通过链接引用。

## 编写前置与现状依据

先读取相关代码并更新需求根 README.md 的汇总，再根据其中目标、进度和问题拆出本任务。列对应需求/验收 ID、计划工作包、汇总依据/问题 ID、核查基线和现有行为/缺口；定位到实际文件及符号/入口。新文件与新接口标为拟新增，尚未核实的依赖列核实动作，不编造已存在实现。

## 目标、范围与契约

说明输入、输出、前置和兼容边界；write_scope 覆盖具体代码/文档/测试/公共文件，不默认全仓库。

## 多 Agent 执行与交接（必填）

- 启动条件：列实际依赖与待核实项的解除条件；不能因任务文件存在就视为就绪。
- 只读输入与独占产物：`read_scope` 只列额外只读依赖，待修改文件仅列 `write_scope` 且修改前仍须读取，不双列；目录包含子路径，拟新增文件也需声明。
- 可并行对象：填写 `parallel_group` 及可同时工作的任务；没有并行空间时填 null 并说明真实依赖。
- 公共文件：逐项列唯一写入任务，本任务只消费或提交变更需求；需要共享写入时链接具体串行调度/领取交还规则。
- 输出与接收者：列可交接文件、契约版本/采用提交、实际验证证据和未解决问题；后续接线/联调指向明确任务。
- 环境与失败处理：未来并行运行时隔离工作树/构建输出/端口/测试数据；无法隔离则串行。缺陷回派原文件所有者，不由联调任务无限扩大写入范围。

未认领 `owner: null`，规划中的任务默认 `backlog`；不能把拟负责角色写成已安排 Agent。代码未知时先核实再细化，仍可先拆出独立明确的部分。

## 执行与验收

- [ ] 完成实际产出与交接。
- [ ] 实现任务按改动验证；纯文档任务只做必要目录/链接检查，不运行构建、测试或 CI。
- [ ] 如实区分通过、失败、未执行和不适用，任务明细、看板与根汇总同步。
- [ ] 前置 ID 有效且无环，写入无未解释重叠，公共文件已按约定交接。

## 阻塞、交付与记录

记录唯一负责人、阻塞原因、解除条件、最终文件和证据；未分配负责人为 null。认领、状态变化、发现/解决问题时同步根汇总的进度与问题条目。无实际实现/验收不能填 done。跨模块联调另建任务并等待前置交付。
