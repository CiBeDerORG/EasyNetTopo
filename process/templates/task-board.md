# <需求名称>任务看板

复制到 `process/<feature>-<状态>/task/README.md`。先读取并更新根汇总，按实际计划和代码依据拆任务；每项任务单独使用 `task-<任务编号>-<任务名称>.md`，本文件只保留看板、依赖与交接摘要。

“需求拆分”必须落到本看板及实际任务文件，不能只登记待拆工作包。资料不足的内容先建立核实任务，后续任务保留实际启动条件；不因缺少证据编造实现或宣称就绪。

## 尚未拆分的计划

| 计划明细 | 待细化内容 / 原因 | 下一步 |
| --- | --- | --- |
| 关联具体 plan-编号-名称.md | 按事实填写 | 先补依据/契约或生成独立任务 |

待拆分计划不计入任务数、任务状态或完成率；没有任务明细时写“尚未拆分”，不预填已认领或完成。

## 实际任务

| 任务 ID / 明细链接 | 对应计划 | 状态 | 负责人 | 前置 | 问题 / 交付依据 |
| --- | --- | --- | --- | --- | --- |
| 创建 task-任务编号-任务名称.md 后登记 | 具体计划 ID / 链接 | 读取明细 | null 或实际认领者 | 实际任务 ID | 汇总问题 ID 或明细证据 |

上表是占位，不能算实际任务。单项状态以明细为准，认领/阻塞/交付/完成时同步看板和根汇总；统计明确完成数、总任务数与单列的取消项。

## 并行与交接

强制列出依赖图/表、可并行批次、需串行的理由和以下公共所有权表；不能只写“可多 Agent 并行”。接线与真实联调安排在前置交付后，实际任务状态以明细为准。

| 公共文件 / 资源 | 唯一写入任务 | 只读消费者 | 交接 / 调度条件 |
| --- | --- | --- | --- |
| 按真实范围填写 | 稳定任务 ID；负责人未知仍为 null | 实际任务 ID | 采用提交、版本、产物与证据；跨需求引用明确调度 |

任务依赖无环、ID 不悬空、所有写入重叠有串行安排；构建输出/端口/临时数据也需隔离。根汇总/索引/看板/任务元数据由协调者集中同步，各任务独占证据路径。仅文档变更不运行构建、测试或 CI。
